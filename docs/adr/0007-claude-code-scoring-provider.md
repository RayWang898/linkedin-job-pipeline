# 0007. Scoring can run through Claude Code on a Claude subscription

The maintainer ran out of Anthropic API credit while still having a Claude subscription, and many job seekers are in the same position: they pay for Claude, not for the API. Scoring was hard-wired to the Anthropic SDK (`call_model` raised for any other provider).

Decision: `scoring.provider: "claude-code"` makes every model call a `claude -p` run (Claude Code in print mode, `scripts/execution-python/providers.py`). The tool's input schema goes in `--json-schema` and the answer comes back as structured output, so the same validation and the same retry-once-then-skip path apply as with the API. Each call runs with no tools (`--tools ""`), no settings sources, no MCP servers and no saved session, in an empty temporary folder, so it cannot read or change the workspace. `ANTHROPIC_API_KEY` is removed from its environment, because with that variable set `claude` bills the API key instead of the subscription. `--bare` is not used: it ignores the subscription login. The default provider stays `anthropic`, and with it nothing changes.

Trade-offs: calls count toward the plan's usage limits, which a full day (several hundred calls) can reach; the jobs left unscored are skipped and the day can be scored again later. Each call starts a process, so a day is slower than with the API. Prompt caching is whatever Claude Code does on its own; the engine's `cache_control` marks are not passed on. Token counts in the summary are what `claude` reports. `--dry-run` checks only that the `claude` command exists, because checking the login would itself use a call.

The real output format was checked by hand on Claude Code 2.1.310 (one call with Haiku 4.5, about 2 seconds): the result object has `is_error`, `usage` with the same four token fields as the API, `structured_output` with the schema answer, and the same answer as a JSON string in `result` (the code falls back to it). The fake `claude` command in `tests/fakes/bin/` follows that format. The test suite cannot catch a future change to it.
